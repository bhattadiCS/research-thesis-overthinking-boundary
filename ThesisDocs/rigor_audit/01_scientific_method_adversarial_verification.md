**Judgment.** The pair was never a same-code, single-flag experiment, and both reports overstate it: `Scientific_Method_Verification_Report.md:19` even attributes the bf16 ladder to "an NVIDIA L4 GPU," which is **false** (a 24 GB L4 cannot hold 61.1 GB; the L4 ran the *4-bit* side in April). The residual unexcludable confounds are hardware/torch-stack and three months of generation-code drift (the *generation* behavior, unlike the grading, cannot be replayed without a GPU rerun).

**Verdict: CONFIRMED-WITH-CAVEAT** — the scientific conclusion ("the early-step dip was a quantization artifact; the late boundary is not") survives adversarial re-testing, but the isolation *claim as written* ("differ only in the quantization flag" framing) is NOT SUPPORTED and both reports need the correction. A clean modern pair (bf16 vs 4-bit, same July code, same box, 500 tasks) is a cheap pre-registered experiment — HANDOFF TO MODULE 4 candidate (via Module 3).

## Axis 3 — Temperature (0.1 / 0.6 / 1.0)

**Claim under test:** within each model+dataset cell, temperature is the only thing that varies across the three temperature blocks — same questions, same order, same seed, same everything else.

**Evidence chain:**
- **Same questions, same multiset:** for **all 52 populated cells**, the sorted task_id list per temperature is identical across the three temperatures, with zero duplicate task_ids within any temperature block (`m1_data_checks.py`, columns `temp_multiset_identical=True`, `dup_task_in_temp=0` for every cell — including the corrupt GPQA cells, whose `trace_runs.csv` is clean).
- **Seed:** `trace_runs.csv` `seed` column = {7} in every cell, and every well-formed `run_id` in every cell ends `__seed7` (both checked exhaustively). The seed does **not** vary with temperature — temperature is not confounded with seed value. Note on how seed enters generation: `real_trace_experiments.py:2473` calls `set_seed(seed)` once at the start of each (temperature, seed) block, so all three temperature blocks start from the same RNG state; downstream draws then depend on batch composition and resume history, which is why runs are statistically- rather than bitwise-reproducible. This is a reproducibility nuance, not an isolation failure.
- **Same order:** structurally, the task list is built once (`load_tasks`, shuffle seed 17) and iterated identically inside each temperature block (`real_trace_experiments.py:2462-2476`). Empirically, the first-occurrence order of task_ids per temperature block in `trace_steps.csv` is identical across temperatures in **48/52 cells**. The 4 exceptions are exactly the corruption-affected GPQA cells, where `reconcile_existing_outputs` rewrote the file sorted by (run_id, step) on a resume (`real_trace_experiments.py:1311`) and re-collected runs were appended at EOF — i.e., the CSV row order there no longer reflects presentation order; presentation order itself is fixed by code for every cell.
- **Same config across temps:** all three temperatures run inside a single CLI invocation per cell (one command string per cell in the manifest), so max_steps/max_new_tokens/prompt/batch size cannot differ across temperatures within a cell.
- One statistical caveat (disclosure, not violation): with a single seed, each (task, temperature) pair has exactly one replicate, so per-temperature differences at the run level carry sampling noise from one stochastic decode; the published temperature comparisons aggregate over 500 tasks × 13 models, which is adequate for the direction claims made.

**Verdict: CONFIRMED.**

## Axis 4 — Dataset/benchmark grading (identity across models) + label trust

### 4a. Is the grading function identical for every model within a benchmark?

- The entire grading path is `answer_type`-keyed, never model-keyed: `verify_answer` (`real_trace_experiments.py:717-723`) dispatches on `task.answer_type` to `math_answers_equivalent` (math), `normalize_mcq_answer` equality (mcq), or `normalize_answer` equality (number). `answer_type` is set exclusively by the dataset loaders: gsm8k→`number` (line 995), math→`math` (1046), arc→`mcq` (1084), gpqa→`mcq` (1120).
- `grep`-verified: no `model_alias`/`model_name`/`hf_name` conditional appears anywhere in the parse/extract/normalize/verify functions (`parse_generation`, `extract_answer`, `extract_typed_answer`, normalizers) — parsing and grading are model-blind.
- Collection-time call site: `is_correct = verify_answer(context["task"], parsed["answer"])` (line 2053) and `utility(correct, step) = correct − 0.05·(step−1)` (lines 726-727, 2101) — same for every model.
- Gold targets: expected_answer arrays byte-identical across models per dataset (Axis 1 evidence).
- **Grader-quality footnote (new finding):** `normalize_mcq_answer("N/A")` returns `"A"` (the standalone-letter regex at line 673 matches the `A` after the slash), so a model that *declines to answer* with a literal `N/A` is credited whenever the gold letter is A. Exhaustive scan of all 26 ARC/GPQA cells (`m1_na_scan.py`): 92 N/A-style answer rows exist; **10 are falsely credited** (`('N/A','A',correct=1)`: 3 in `mistral_7b_instruct_v0p3__arc`, 2 in `qwen2p5_14b__gpqa`, 5 in `yi_1p5_9b_chat__gpqa`), 82 are graded 0 (accidentally correct outcome). This is model-agnostic (any model emitting N/A is treated the same), so *cross-model identity holds*; it is a (tiny: 10 of ~331K MCQ rows) absolute-quality defect.

**Verdict (identity): CONFIRMED.**

**The decisive defect:** `regrade_traces.py:33-35` (`_answer_type`) maps task_source to only `"math"` or `"number"`. ARC and GPQA rows — collected and graded as `"mcq"` — are re-graded as `"number"`, under which any stored answer that is not the bare letter (e.g. `"B) mitochondria"`, `"Option C"`, an answer containing any digit) mismatches the gold letter. A second defect compounds it: `regrade_traces.py:39` reads the CSV with pandas' default NA parsing, so stored literal answers like `'N/A'` (and `'NaN'`/`'None'`-class strings) are swallowed to NaN and re-graded as `""` (line 46).

**Empirical characterization** (two independent re-implementations of the tool's per-row loop — `m1_flips.py`/`m1v_flips_math.py` and Module 2's `regrade_flips.py` — agree per-cell everywhere both ran; validated against the real tool by running `regrade_traces.py --dry-run` on scratchpad copies of three cells, per-cell counts matching **exactly**: `mistral_7b_instruct_v0p3__arc` 2,044/12,000 = 17.03%, `yi_1p5_9b_chat__gpqa` 1,629/13,455 = 12.11%, `deepseek_r1_distill_7b__math` 0/21,000):

| Dataset | Rows | Flips under TOOL semantics | Flips under CORRECT semantics |
|---|---:|---:|---:|
| gsm8k (all 13 cells) | 195,000 | **0** | **0** |
| arc (all 13 cells) | 156,000 | **7,596** | 3 |
| gpqa (all 13 cells) | 174,770 | **4,688** | 47 |
| math (all 13 cells; tool == correct semantics for math) | 273,000 | **1** | **1** |
| **Total, all 52 cells** | **798,770** | **12,285 (1.54%)** | **51** |

- The 12,284 ARC/GPQA tool-semantics flips are **entirely the answer-type artifact**: direction is overwhelmingly 1→0 (7,596/7,596 arc; 4,648/4,688 gpqa), i.e., correct MCQ answers de-credited when graded as numbers. Per-model spread confirms the mechanism (models that answer with bare letters flip ~0: `qwen2p5_7b` arc/gpqa = 0; verbose answerers flip most: `qwen2p5_0p5b__arc` 22.5%, `mistral_7b_instruct_v0p3__arc` 17.0%, `yi_1p5_9b_chat__arc` 17.0%).
- Of the 51 correct-semantics flips: **40 sit on corruption-garbage rows** (CSV fragments whose "run_id" is LaTeX text — see Axis 5; their `task_source` is field-shifted so they fall into the number path and compare empty-to-empty), **10 sit on the `'N/A'` rows** described in §4a (the raw CSV field is the 3-byte string `N/A`; collection graded it (falsely) correct via the letter-A extraction; `pandas.read_csv` in the regrade path swallows `N/A` as NaN → `""` → grades 0 — not grader *drift* but the one place where a collection-time false positive and a pandas NA-parsing artifact coincide), and **1 is the single genuine disagreement** described in §4c. (Ten further NA-swallowed `'N/A'` math answers exist in `mistral_small_24b_2409__math` but grade 0 under both readings — no flip; checked row-by-row, `v_mistral_small_flip.py`.)
- **Conclusion: the on-disk `correct` labels are consistent with the current audited grader to within 1 row in 798,770.** GSM8K: 0 drift in 13/13 cells (the 06-20 re-grade did its job; nothing changed since). ARC/GPQA: 0 real drift in 26/26 cells (collected post-`122358a` with today's exact mcq semantics); the dry-run's flips there are the tool grading them with the wrong answer type. MATH: 0 drift in 12/13 cells and exactly 1 row in the 13th (§4c) — including `qwen2p5_7b__math`, the only cell with rows predating the last math-grader change (`8beba2d`).
- Reconciliation with `074bc70`: full-matrix, all 52 cells, the tool's own semantics give **12,285 flips / 798,770 rows = 1.54%** — the commit message's "~1.62%" does **not** reproduce over the 52-cell denominator. Operationally plausible: the tool is unmemoized `df.iterrows()` + sympy fallback, and the slowest MATH cells are pathological (my *memoized* replication needed 45 min for `phi_4_mini_instruct__math` and 29 min for `yi_1p5_9b_chat__math`; the interrupted session's own background batch on that cell group died without logging a single cell).
