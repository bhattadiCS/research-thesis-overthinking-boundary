# Frontend implementation notes

Frontend owner: Agent A. New framework-free files are `static/index.html`, `static/styles.css`, and `static/app.js`. No CDN, package install, research source, frozen evidence, model or dependency changes are required. The static asset routes are `/`, `/styles.css` and `/app.js`.

The interface provides a 3,000-character prompt, three arithmetic/mathematics examples, the two supported domains, learned/heuristic policy selection, run/cancel controls, and responsive side-by-side comparison panels. It shows completed-response count separately from the selected candidate's response index; response summaries, candidate answers and expandable raw output; measured completion/input token counts and elapsed time; and the early decision with supplied current/next correctness estimates and drift. Terminal response five does not display a next-response estimate. Confidence is read only from the trusted observation field, never extracted again from raw generated JSON.

The exact SSE contract is implemented. Token events replace cumulative decoded text and current response counts; they are never appended or counted as one token per callback. Response costs/tokens are summed once per response and then replaced by authoritative decision/final totals. The early panel is frozen after STOP, while baseline-only events continue. Decisions preserve a selected earlier answer separately from the number of responses executed. Events are deduplicated by sequence number, including a possible zero initial sequence. EventSource reconnection uses the browser's Last-Event-ID behavior, and a run snapshot reconciles any missed events or terminal state. Native EventSource error notifications are separated from server error message events.

The page describes one real shared prefix, followed by baseline-only continuation. Savings are labeled as the early arm's avoided continuation budget, and the final strip also reports physical completion tokens generated once for the comparison. Answer-text equality has neutral styling and an explicit whitespace/case string-match explanation. It is not labeled correctness or semantic equivalence. The headline is "Watch a policy decide when to stop." The learned 0.05 value is described as a continuation penalty and hidden when selecting the confidence heuristic; it is not presented as money. The notes distinguish response revisions from within-response tokens and make no posterior, accuracy-preservation or optimality guarantee. No mock generation or replay is presented as live.

Actual missing-model, unavailable-predictor, busy-server, failed-request and interrupted-stream states are handled. An unavailable learned predictor permits switching to the heuristic. Run configuration is locked during execution, cancellation retains partial output, and any failure keeps inspectable responses. Dynamic text uses textContent rather than generated HTML. Native labels/fieldset controls, visible keyboard focus, a skip link, non-chatty status announcements, reduced-motion handling and mobile stacking are included.

Validation: `node --check demo/early_stopping/static/app.js` passes. An independent HTMLParser check found 65 unique DOM IDs and confirmed all 38 literal JavaScript ID references exist. Coordinator is performing real backend/browser verification; these static checks alone are not a claim of visual or live browser verification. Agent B's independent design review was incorporated: 3,000-character backend limit, neutral answer matching, retained-candidate indexing, no terminal next-step estimate, shared physical-cost accounting, and startup snapshot restoration.

On page load, the latest server run is restored from its snapshot, including its prompt, configuration, events and terminal/partial result. A current run reconnects to SSE and offers cancellation. A completed run is explicitly labeled as saved previous results, not new live generation, and leaves the run controls usable. Restoring does not start generation. Version/run-ID guards prevent stale asynchronous snapshots from replacing a newer comparison. Transport reconnection also reconciles the currently open run's snapshot and deduplicates the subsequent SSE history.

After inspecting the coordinator's real-model desktop/mobile screenshots, key body/summary/decision text was enlarged to 12–13px, labels to at least 10px, and controls to 12–13px. Unstructured responses now have a visible neutral notice inside the response card and, when selected, inside the selected-answer box. The flag uses only the supplied `observation.parse_success === false` (or numeric zero); it does not reinterpret raw JSON, alter extraction, change saved answers or modify any stopping/token calculation. The original tiny footer note remains as secondary provenance.

## October 14 usability revision

Rebuilt HTML/CSS around a plain-language outcome before the numeric panels, with an always-visible five-response timeline. All 67 prior DOM IDs and every existing response-template class hook are preserved. New hooks are `theme-select` (system/light/dark), `local-model-note`, `model-size-note`, `outcome-card`, `outcome-heading`, `outcome-summary`, `outcome-quality`, `run-timeline`, `early-retained-details`, `early-retained-answer`, `baseline-retained-details`, `baseline-retained-answer`, `decision-explainer`, `estimate-details`, `gain-explanation`, `estimate-gain` and `estimate-required`. The timeline uses five `li[data-step]` items, `.timeline-marker`, `.timeline-label`, `.timeline-status` and the classes `is-shared`, `is-baseline-only`, `is-stop`, `is-complete` and `is-active`.

Themes use CSS custom properties throughout, support `html[data-theme="light"]`, `html[data-theme="dark"]`, and `system`/unset via the OS preference, and change real surfaces and text rather than only control appearance. Body/explanation text is generally 14–16px; secondary labels are at least 12px. Early-path accents are teal, five-response accents indigo, and the savings strip is neutral rather than green. Input-token/time metrics are secondary to retained-answer status and response/generated-text counts.

Response cards are native collapsed `<details class="response-card">` elements with a `<summary class="response-heading">`; all their original descendant hooks remain. The coordinator owns JS that opens only the currently generating card and collapses it after completion. Raw records, q/p details and method/technical notes start collapsed. Invalid formatted answers belong in retained-record details while the main answer/status stays readable; the coordinator owns this rendering behavior. A visible `data-unstructured=true` row badge keeps the format issue discoverable even while the row is closed.

The simple headline and limitations do not claim that the model detected overthinking, verified an answer or proved that continuing helped. The intro uses “help enough” to preserve the positive-gain-below-cost case. The decision explanation separates estimated improvement from a continuation penalty, while q/p remain fitted estimates rather than the model's untrusted reported confidence. This revision edited only index.html, styles.css and these notes; app.js and all model/selector/backend behavior remain coordinator-owned.
