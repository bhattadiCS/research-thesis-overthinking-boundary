# Usability revision, 14 October 2026

The coordinator inspected the user's actual open Edge tab with Browser Use, reran the exact logarithm prompt, and used the confusing result to guide the revision. Browser Use was also used after the changes to run a fresh comparison, switch Dark/Light/System themes, and inspect both the score calculation and unchanged retained record. These were actual local-model generations, separate from the synthetic regression fixtures.

The old page emphasized 59.8% token reduction, showed a malformed JSON payload as a selected answer, and called differing payload strings different answers. In the user's run those strings differed in confidence formatting; all five responses failed the existing parser. The old wording did not support a meaningful mathematical-answer comparison.

The revised interface leads with **Stopped after 2 of 5 responses**, explicitly says three responses were skipped, and marks responses three to five as full-run-only on a timeline. Token reduction is separately labeled as generated-text accounting, with physical work for the entire comparison disclosed. A selected malformed candidate is no longer promoted to the primary answer: the page says **Answer could not be read reliably** and **Answer comparison unavailable**. The original exact string remains available under its disclosure. A readable earlier selected answer remains displayable if a later observation is malformed. No parsing, policy, model parameter or response was changed to improve appearances.

The STOP explanation displays the actual calculation in plain language: fitted score 0.3% now, 0.6% after another response, approximately +0.3 percentage points of improvement versus a 5.0-point continuation penalty. The exact gain is +0.3025490664 points and net gain is −4.6974509336 points. Positive improvement can still be below cost; a stop does not claim confidence or correctness. Technical scores start collapsed. Near-zero signs, rounded ties, exact ties, zero-valued scores and the terminal horizon are handled explicitly.

New Light, Dark and System themes use higher-contrast text and consistent teal/indigo path colors. Theme choice persists. Completed response logs, literal records and calculations start collapsed; the response being generated opens to show live output. Model-size limitations and the absence of automatic correctness grading are visible near the prompt.

Verification completed:

- **Eight synthetic browser groups** passed with zero page errors and no model generation. They cover malformed selected records, retained prior valid answers, gain-versus-penalty arithmetic, horizon/no savings, blank/zero scores, exact ties, tiny positive net, and persisted mobile themes. Key checked text exceeded 4.5:1 contrast: minimum 8.10:1 dark and 5.46:1 light. This is a focused readability check, not comprehensive accessibility certification.
- **25 existing backend tests** passed. Backend scheduling, cost/selector semantics and model files are unchanged.
- The exact user's logarithm problem was tested live through Browser Use on the final UI: two early responses and five full responses; 68 versus169 generated tokens; all five malformed. The page correctly withholds an answer-quality/overthinking conclusion. Expanded controls expose the original strings and the calculation without silently extracting a new answer.
- Actual-run desktop/mobile captures in both themes were checked against the final code, with no horizontal overflow or page errors. All36 original thesis/source baseline hashes remain unchanged; no tracked preexisting source changed. No dependencies, research data, training, grades, publication or Git history were changed.
