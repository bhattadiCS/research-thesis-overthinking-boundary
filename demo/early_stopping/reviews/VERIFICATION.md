# Live UI verification

The implemented app is under `demo/early_stopping/`. Start it with `./demo/early_stopping/start.ps1`; the local server is at http://127.0.0.1:8765. The launcher opens installed Chrome. No frozen research source, artifact, dependency or thesis file was edited.

| User-visible requirement | Authoritative evidence |
| --- | --- |
| Type a prompt and start actual generation | `browser_smoke.py` fills the real page and clicks Run; `browser_smoke.json` records the completed actual local Qwen/CUDA run and exact static-source hashes. This uses no replay or synthetic generation. |
| See output arrive in real time | The browser observes decoded text while the response still says Generating. `live_smoke_events.json` and `live_smoke.json` separately record token arrivals before all five response endings. |
| Compare stopping with continuing | One actual generated prefix is delivered to both arms until STOP, then only baseline events continue. The final browser run has two early responses, five full responses, 62 versus 167 completion tokens and 320 versus 1,124 input tokens. The final early answer/cost stay frozen. `completed_run.json` retains the actual event history; `math_design.md` independently reviews the accounting and predictor decision. |
| Understand the comparison | The page shows selected candidate/response index, consumed responses/tokens, supplied fitted q/p estimates and drift, and STOP reason. It explicitly distinguishes physical comparison work from an early-only run's avoided suffix, and answer-text agreement from correctness. |
| Cancel and use the app again | The final actual browser test cancels during decoding, sees a cancelled terminal state with no final savings, then successfully runs a new comparison with the same resident model. |
| Refresh/reconnect and use a narrow screen | The actual browser test reloads the running comparison and restores a completed one in a fresh mobile context with no new generation. Final 1440px/390px images have no horizontal overflow; final labels, counters and unstructured-response notices match the actual saved events. |
| Recover from missing resources/errors | `ui_states.py` uses explicitly synthetic HTTP fixtures, no generation, to verify missing model, missing predictor with heuristic fallback, failed start, and unreachable server messages. |

All **25** isolated backend tests pass (14 runtime/state, 11 HTTP/SSE). `tests/backend_test_record.json` pins exact commands and source hashes. They check immutable early state, retained-answer cost, unequal token lengths, terminal-first decisions, cancellation, errors, stream reconnection and HTTP boundaries. `node --check static/app.js` passes. The actual final browser test and final rendering report no page execution errors. Screenshots were visually inspected, including the live comparison, completed desktop, and mobile layouts.

The connected Edge browser profile rejected local pages with `ERR_BLOCKED_BY_CLIENT`; no Edge security setting was changed. Verification instead used the existing installed Chrome in an isolated automated-test context with its normal sandbox. The launcher opens Chrome for normal interactive use. The first browser-test attempt used expression-string polling that conflicted with the page's strict CSP; the test was corrected to locator polling. The application's CSP was retained. Two HTTP rejection defects found by independent review were fixed and regression-tested: malformed Origin parsing, and small unread-body resets on Windows. The startup-restoration gap and initial small text were also fixed and reviewed.

These are new interactive demonstrations, kept separate from the thesis's frozen research evidence. Both retained examples contain adverse model/parser behavior: 12+8 selects24; 2+2 initially produces4, then malformed output causes the existing fallback extractor to select100. That behavior is preserved and visibly flagged as unstructured output. This verifies that the UI faithfully exposes the existing instrument; it does not establish correct answers, useful adaptation, calibrated probabilities, accuracy preservation or Bellman optimality. The early policy operates between complete responses, not at individual risk-driven token boundaries.

Independent reviews are `math_design.md`, `backend_test_review.md` and `../agent_frontend.md`. Final-byte/current-service checks and source preservation are in `completion_check.json`; the new demo files are hashed in `../artifact_manifest.json`. No research collection or training, production regrading, publishing, commits or pushes were performed. The explicitly identified live smoke generations are UI verification only.
